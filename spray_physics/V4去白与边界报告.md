# V4：逐帧深度去白，再捕捉边界

版本：4.0.0-alpha1。日期：2026-10-30。

本报告保留旧V4差分恢复基线；最新分层估计见[V4.1分层去白优化报告](V4_1分层去白优化报告.md)。

## 1. 用户要求与流程修正

用户确认的白斑是起喷前已经存在、位于视窗左右约9点和3点方向的固定打光亮区。要求对每一帧先去除这些背景亮区，生成去白序列及动画，再对处理后的图像捕捉喷雾边界。

V3直接利用原图和背景预测分割，在原图上画边界；这不满足上述处理顺序。V4将两阶段严格拆开：

1. 当前原图及空背景输入深度恢复器，估计背景扰动并输出连续灰度的去白图。
2. 70张去白PNG全部写入`cleaned_frames/`后，才启动边界模块。
3. 边界模块重新读取这些PNG；它不读取原始喷雾图或原始空背景。
4. 分别导出纯去白动画和去白图上的边界动画。原图仅放在另一个明确标识的对照动画中。

整个文件夹自动处理，无需逐帧手工擦除。

## 2. 查找的工具及实际采用方式

- [NAFNet官方项目](https://github.com/megvii-research/NAFNet)、[ECCV 2022论文](https://arxiv.org/abs/2204.04676)：图像恢复网络。本项目参考其公开结构改写成双图背景条件恢复器，使用PyTorch直接运行，没有安装BasicSR或调用自然图像预训练权重。MIT声明保存于`licenses/NAFNet-MIT.txt`。
- [BackgroundMattingV2官方项目](https://github.com/PeterL1n/BackgroundMattingV2)：其当前图加额外空背景的分离接口与本任务吻合，作为参考设计。它的现成人像权重不能直接视为柴油喷雾去白模型，本轮没有把它的预测作为去白结果。

本轮实际运行的是针对本任务训练的NAFNet结构改写模型，不是官方原版的直接复现，也没有现成模型已经验证本组实验效果的结论。

## 3. 深度比对的判定依据

恢复器输入当前帧I、原始空背景B及双极性变化通道，预测背景变化/噪声N，输出有符号喷雾观测贡献：

`R = I - B - Nθ(I, B)`

空背景参考先依据视窗外静态区域进行有限光度校正。原始背景始终保留；模型不按“像素是白色”来决定删除，也不使用边界分割掩膜把原图擦黑。恢复网络的连续输出覆盖整个视窗。

深度比对通过配对监督训练：合成样本同时具有已知空背景、喷雾贡献和光照/噪声扰动，损失分别约束背景残留、喷雾贡献误差和梯度保留。背景损失与前景损失分别归一化，防止大量背景压过短小喷束；整幅抹黑会受到前景损失惩罚。

去白显示使用`abs(R)`及全序列固定3倍增益，将增亮和变暗贡献统一显示在黑底上。没有逐帧自动拉伸；该图是观测贡献的可视化，不是柴油浓度或散射强度的定量反演。完全相消、过曝或无对比的喷雾纹理仍无法保证恢复。

必须如实区分：固定背景剔除主要来自参考背景项，深度网络学习其变化和噪声修正。本轮相对简单差分的合成误差改善很小，不能宣称深度学习已经大幅提高白斑重合区的恢复能力。

## 4. 实际训练与检查

环境沿用独立CUDA PyTorch环境。恢复器407905参数，训练800步；边界网络491606参数，在冻结恢复器输出上训练500步。batch为4，训练尺寸320，全部训练约377秒，峰值显存约995MiB。

训练仅使用合成配对监督和前3帧空背景，真实人工喷雾边界标注为0。第4、5帧留作同序列空背景检查。边界阶段训练与推理都只接受恢复图，训练时也模拟8位PNG量化。

| 检查 | 结果 | 解释 |
|---|---:|---|
| 合成前景贡献MAE | 0.01150 | 灰度归一化到0—1，不是真实误差 |
| 合成背景MAE | 0.01258 | 简单差分对照0.01269，改善有限 |
| 合成前景能量比 | 0.9768 | 约97.7%，不是实际喷雾保留准确率 |
| 仅恢复图边界的合成验证IoU | 0.7949 | 与V3分布及输入不同，不能直接混比 |
| 第4帧白区平均灰度 | 原图162.64，去白2.19 | 已知无喷雾，固定显示增益3 |
| 第5帧白区平均灰度 | 原图162.65，去白2.16 | 已知无喷雾，固定显示增益3 |
| 两帧去白白区99%分位灰度 | 均6 | 仍有低幅噪声，不声称所有像素归零 |
| 实际去白PNG与边界输入哈希 | 70/70一致 | 证明边界从已保存的去白图读取 |
| 两段结果动画 | 各70帧 | 每帧100ms慢放，不代表实际采集速度 |
| 原始图像SHA256 | 70/70与原清单一致 | 原始序列未被修改 |
| 新增恢复流程检查 | 5项通过 | 包括训练到保存、恢复、边界及批处理 |

| 桌面入口 | 完整70帧通过 | 先去白、后边界的实际子进程调度 |

白区检查区域由背景高亮区域生成，仅用于评分，没有作为擦除蒙版参与图像处理。推理与输出约30秒，包含文件读写和动画编码，不是独立网络吞吐基准。

## 5. 效果自评与后续

起喷前固定左右白斑明显压暗；喷雾出现后，去白动画显示黑底观测贡献，没有继续把原始打光白斑当作最终动画背景。边界动画也只叠加在去白图上。

白斑重合区的喷雾仍偏弱，晚期保留了明显暗带，窗框还有少量变化残留。因此目前验证了处理顺序、逐帧输出和背景抑制，不等于已完整恢复重合区域的真实喷雾。下一阶段应增加真实恢复监督或分层成像模型，并复核薄喷雾保留，不能靠提高删除强度把喷雾一起抹掉。

物理约束目前仍限于成像分解、视窗和喷嘴关联，没有接入定量喷速、阶段切换及时序物理网络。40bar为环境背压记录。当前不导出可用作实验结论的物理面积或速度。

## 6. 运行方式与结果

本机双击`启动工具.bat`，点击“载入本机去白示例”，选择新的结果位置，运行整段序列。处理其他序列时选择“V4先去白再识别”，加载V4配套权重，检查一次标定及空背景帧。

命令行示例，`python`须为已安装PyTorch的独立环境解释器：

```powershell
python restore_spray.py train --model residual --data deep_runs/数据 --output deep_runs/V4训练 --steps 800 --boundary-steps 500 --device cuda
python restore_spray.py process --config 设置.json --checkpoint deep_runs/V4训练/pipeline_best.pt --output deep_runs/V4结果
```

批处理在`process`中增加`--batch --input 父目录 --output 批处理结果`，逐子目录重估背景和几何。数据准备方式沿用`deep_spray.py prepare`；新输入默认重新标定，显式`--reuse-geometry`才复用。

| 文件 | 含义 |
|---|---|
| `cleaned_frames/` | 每帧真实保存的去白PNG，是后续边界的唯一图像输入 |
| `removed_background/` | 恢复器估计的背景，供核查是否误吸收喷雾 |
| `逐帧深度去白.gif` | 纯去白结果，不含原图背景列 |
| `boundary/去白后边界动画.gif` | 在去白图上识别和叠加的边界 |
| `原图与去白对照.gif` | 左原图、右处理图，仅供对照，左边保留白斑是原始输入 |
| `frame_mapping.json` | 原图哈希与去白图哈希映射 |
| `boundary/boundary_inputs.json` | 边界模块实际读取文件的哈希及状态 |
| `restoration_summary.json` | 两阶段、权重哈希及处理统计 |

原图、环境、私有配置和权重不直接进入源码Git提交；配套本地试用包保存训练权重及实际动画，源码、许可、报告和去路径的验证摘要推送到原专用分支。
